**Spiritual-level switch** (`config.spiritual: full | light | secular`): `full` prints all ✦ items. `light` keeps the art,
mudrās and Oṃ/Śānti mantras but swaps cakra and yantra practices for their secular twins. `secular` swaps every
spiritual activity for its secular alternative and drops the mantra/yantra/cakra foundation pages. Each of those pages
is replaced by a matching secular page, such as "Sound & humming" or "Geometry for calm", so the **page count stays 88**.

## 2. Content schema (data → templates; nothing is hand-written per week)

```
booklet/
  config.json              mother_name, partner_name, baby_nickname, due_date, title, subtitle,
                           languages[], theme (colour|lowink), spiritual (full|light|secular),
                           size (a4|a5), bleed (true|false), locale (en)
  content/
    weeks.json             [{ week, trimester, theme:{key, sa_deva, sa_iast},
                              size:{fruit_key, cm, g}, baby:{milestone, senses[], evidence_note, badge},
                              tradition_note?, activities:{mind, body, heart, spirit, nourish} (ids),
                              partner_task, journal_prompt, calm_minute, art:{type, seed} }]
    activities.json        { id: { category, title, badge, minutes, trimesters[], steps[],
                              stop_if[], doctor_check, secular_alt, source_ids[], evidence_note } }
    mantras.json           { mantras:[{id, deva, iast, meaning, pron[], source_id, tradition_note, alt}],
                             lullabies:[{id, lang, script_text, iast_or_roman, meaning, author, pd_status}] }
    nutrition.json         [{ id, nutrient, why, foods_veg[], foods_nonveg[], recipe:{name, ingredients[],
                              steps[]}, do[], dont[], source_ids[] }]
    references.json        [{ id, authors, year, title, venue, url, type, confidence, verify }]
    stories.json           [{ id, source_tradition, title, text, label }]   (original retellings)
    glossary.json          [{ term_iast, deva, meaning }]
    pages.json             ordered page list → template + data bindings (drives page numbers/contents/index)
  i18n/en.json             every UI string (labels, headings, safety lines) → translation-ready
  art/  (generated)        mandala-*.svg, sri-yantra.svg, kolam-*.svg, lotus.svg, paisley.svg,
                           moon-phases.svg, fruit-*.svg, mudra-*.svg
  src/  build scripts      (see §4)
  research/                research-notes.md, evidence-table.csv  ✅ done
```

`evidence-table.csv` is the seed for `activities.json`. The 82 activity IDs (M01…K02) carry over unchanged, and a
build check fails if an activity is missing a badge, source or (for BODY/NOURISH) safety lines.

## 3. Design tokens

**Palette (5 colours + neutral text)**

| Token | Hex | Use |
|---|---|---|
| `--ivory` | `#FBF6EC` | page ground (full-colour edition) |
| `--marigold` | `#E0952B` | accents, badges, ornaments. **Not for body text** (low contrast) |
| `--maroon` | `#7A1F2B` | headings, rules, header bands (≈ 9:1 on ivory) |
| `--sage` | `#7F9A7A` | BODY/NOURISH accents, secondary art |
| `--gold` | `#B8913A` | fine linework, frames, foil-like details |
| `--ink` (neutral) | `#2E2A26` | body text (≈ 13:1 on ivory) |
| *lotus-pink* | `color-mix(--maroon 14%, --ivory)` | tints only, derived from maroon (no 6th colour) |

**Low-ink build** (`--theme lowink`): white ground; header bands become 0.5 pt rules; art becomes outlines only;
tints are removed; badges are outline-only. The same layout gives identical page numbers.

**Typography**
- Headings: **Cormorant Garamond** SemiBold (Latin/IAST). Fallback **Noto Serif** if any IAST diacritic
  (ṃ ḥ ṛ ṝ ḷ ś ṣ ṭ ḍ ṇ ṅ ñ) is missing; this is verified in QA.
- Body: **Noto Sans** 10.5–11 pt / 1.45. Writing lines at 8 mm pitch.
- Indic: **Noto Serif Devanagari** (mantras), **Noto Sans Devanagari / Tamil / Telugu / Kannada / Malayalam / Bengali /
  Gujarati**. Full (unsubsetted) TTFs are bundled under `booklet/fonts/` from the official `notofonts` GitHub releases
  (OFL), loaded via `@font-face` with local URLs only.

**Grid**: A4 210 × 297 mm. Trim-safe margins of 14 mm outer/top/bottom, 18 mm gutter (inner), 12-column grid, 4.5 mm
gutters, 6 mm baseline. Running head (section · week) and folio in the footer; odd/even mirroring.

**Art (all generated in code, original, vector)**: mandalas (n-fold rotational + mirror symmetry, with a symmetry test
that compares sampled points after rotation), lotus, paisley, kolam (pulli-grid loop algorithm), moon phases,
fruit-size icons, mudrā hands (simple line illustrations), and the Śrī Yantra (numeric solve of the nine triangles for
classical concurrency, with the residual error reported in QA).

## 4. Tooling

| Need | Choice | Why |
|---|---|---|
| Rendering | **Playwright 1.56 + preinstalled Chromium** → `page.pdf()` | Chromium shapes text with **HarfBuzz**, the same engine as Chrome, so it handles all Indic conjuncts and matras. It is already installed. The same render produces PNG previews. JS can **measure overflow on every page**. |
| Layout model | **Fixed-size page boxes** (one `<section class="page">` per page, `@page { size: … ; margin: 0 }`) | Deterministic, designed pages; running heads and folios are rendered by the templates, so no reliance on CSS margin boxes. |
| Templates | Node ES modules with tagged-template HTML (no framework) | Zero extra dependencies; easy to read and customise. |
| PDF post-process | `pdf-lib` (npm): sets **TrimBox/BleedBox**, metadata, checks page count % 4 | Chromium cannot set print boxes. |
| QA | `pdffonts` (fonts embedded, no fallback fonts), Playwright DOM checks (overflow, clipping, safe-area, min font size, contrast), screenshot of every page | — |
| WeasyPrint | Not used | It has better CSS paged-media support, but Indic shaping depends on Pango/HarfBuzz builds, and it isn't installed. Chromium gives verifiable Indic output in this environment. |

**Outputs** (`booklet/dist/`):
- `booklet-A4.pdf` (home print, no bleed)
- `booklet-A4-bleed.pdf` (216 × 303 mm with 3 mm bleed, TrimBox set)
- `booklet-lowink.pdf`
- `preview/page-001.png …`
- `QA-report.md`

**Build commands** (planned): `npm run booklet:build -- --theme colour|lowink --bleed --size a4|a5`,
`npm run booklet:qa`. These run in an isolated `booklet/package.json`. `booklet/` will be added to the app's ESLint
ignores so the web app's CI is unaffected.

**RGB → CMYK**: Chromium outputs RGB. Most digital printers accept it. For offset printing, the README will document
conversion (Ghostscript or the printer's RIP), and colours are chosen to stay in gamut.

## 5. Build sequence (after approval)

1. Scaffold `booklet/`, download fonts, write tokens/CSS, and build the art generators (mandala symmetry test, Śrī Yantra solver).
2. Write the content JSON (weeks 1–40, 82 activities, mantras/lullabies, nutrition and recipes, stories, glossary, references).
3. **Pilot render**: pages 1–8 + one weekly page (week 24) + one mantra page (p. 20). Render, inspect the PNGs,
   check Indic conjuncts, fix.
4. Generate all 88 pages, plus the low-ink and bleed variants.
5. QA pass: overflow/clipping/safe-area, Indic rendering, contrast, spacing, fonts embedded, page count % 4, factual
   flags. Write `QA-report.md` with the `[needs verification]` register and recommended expert reviewers.
6. Write the README (rebuild, customisation, paper: 100–130 gsm inner, 250–300 gsm cover, duplex flip on long edge, binding).

## 6. Decisions (the defaults in **bold** were applied when the build was requested)

1. **Page budget**: **88 pages, one page per week** (weeks 1–4 combined). Alternative: a true two-page spread per week,
   which is about 130 pages and too thick for saddle-stitch.
2. **Binding**: 88 pages at 100–130 gsm is at or beyond the practical limit of saddle-stitch (risk of creep and
   bulk). **Recommend wire-o/spiral** (lies flat for writing). Saddle-stitch is still supported (page count % 4 = 0),
   with a creep-compensation note.
3. **Outputs in git**: **commit the 3 PDFs + low-res PNG previews** (est. 15–30 MB total) so the booklet is viewable
   without running anything. Alternative: keep `dist/` ignored and build via a GitHub Action artifact.
4. **A5 option**: **delivered after A4 approval**. Weekly pages split into two A5 pages (the template is already
   half-based); other pages get A5 layouts (~150 pp, perfect-bound).
